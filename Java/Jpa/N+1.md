# N+1 문제 정리

## 개념 요약
N+1 문제란 **한 번의 조회로 끝날 줄 알았던 로직이, 연관 데이터를 접근할 때마다 추가 쿼리가 반복 실행되어 성능이 급격히 저하되는 현상**을 의미

## 왜 발생할까?

### ✔ JPA 기본 지연 로딩(LAZY) 전략 때문

[지연로딩 예시_깃허브](https://github.com/Yimin2/intagram_clone/commit/0ab35badde6a5bec7aa0788c0c8ea52f6c64b136)

예를 들어 게시글(Post) 리스트를 조회할 때:

1. `SELECT * FROM post` → **1번 실행**
2. 각 게시글의 작성자(User)를 사용할 때마다  
   `SELECT * FROM user WHERE id=?` → **N번 반복 실행**

```java
List<Post> posts = postRepository.findAll();
for (Post post : posts) {
    System.out.println(post.getUser().getName()); // 여기서 N번 쿼리 발생
}
```

➡ 총 **1 + N 쿼리 발생**


## 해결 방법

### Fetch Join 활용
```java
@Query("select p from Post p join fetch p.user")
List<Post> findAllWithUser();
```
- Post + User를 한 번에 조회하여 추가 쿼리 방지
### EntityGraph 적용
[EntityGraph_예시 깃허브](https://github.com/Yimin2/intagram_clone/commit/4095d3294bc265b6fde62449efe4f16c40a02085)
```java
@EntityGraph(attributePaths = "user")
List<Post> findAll();
```
- 선언적으로 조인 처리
- 레포지토리 가독성 향상
