# 데이터 모델과 SQL

## 정규화

- 데이터 이상현상 방지, 데이터 중복 최소화하여 테이블 분리

## 이상현상

- 삽입 이상 : 데이터 삽입 시, 의도하지 않은 값들도 삽입
- 삭제 이상 : 데이터 삭제 시, 의도하지 않은 값들도 삭제
- 갱신 이상 : 일부 데이터만 갱신되어 모순 발생

## 함수적 종속

- A 속성에 의해 B가 유일하게 결정됨

### 완전 함수적 종속

- 종속자가 PK의 모든 속성에 종속적인 경우

### 부분 함수적 종속

- 종속자가 PK의 일부 속성에 종속적인 경우

## 정규화

### 1NF
- 원자성
### 2NF
- 부분적 함수 종속 제거
- 두개의 PK 중 하나만 속하는 속성이 있으면 안됨
### 3NF
- 이행 함수 종속 제거
- A -> B -> C 가 되면 안됨

## 관계와 조인
### 조인
- 서로 관계 있는 테이블을 SQL로 연결해서 데이터를 조회
- 정규화 된 테이블은 조인 성능이 낮아질 수 있음. (반정규화하여 성능 향상)

## 계층형 데이터 모델
- 트리 구조
- 하나의 부모 여러 자식, 자식은 오직 부모 하나

## 상호베타적 관계
- 둘 중 하나만 해당

## 트랜잭션
- DB에서 하나의 논리적인 작업 단위
1. commit : 저장
2. rollback : 원복

### 트랜잭션 ACID
- atomicity / 원자성
- consistency / 지속성
- isolation / 고립성
- durability / 지속성

## NULL 속성
### NULL 개념
- 비교, 연산 불가, 집계함수에서 제외
- 0과 빈칸과는 다른 개념

## 본질 식별자
- 프로세스 상 현실에 존재하는 식별자
## 인조 식별자
- 인위적으로 생성 식별자
### 장점
- 추가 연산 없이 실제 비즈니스와 무관하게 설계 가능
- 개발, 유지보수 용이
### 단점
- 데이터 중복, 불필요한 인덱스 생성
